# Project Skills — Backlog Gaming

Краткая карта скиллов и фраз, которые удобно использовать в чате.

## 1) `ios-mvp-implementation`

**Когда:** нужно быстро внедрить фичу/фикс с проверкой сборки.  
**Триггеры:**
- «делай»
- «внедри»
- «сделай фикс»
- «реализуй по плану»

**Пример запроса:**
> Внедри это в MVP и сразу проверь сборку.

---

## 2) `timeline-ui-consistency-audit`

**Когда:** есть расхождения стиля между экраном Бэклог и Поток.  
**Триггеры:**
- «приведи к единому стилю»
- «в потоке выглядит иначе»
- «синхронизируй UI между экранами»

**Пример запроса:**
> Поток в карточке и на вкладке Поток выглядит по-разному — выровняй.

---

## 3) `xcodebuild-triage`

**Когда:** проект не билдится, странный destination/simulator, Swift 6 ошибки.  
**Триггеры:**
- «не билдится»
- «почини сборку»
- «ошибка xcodebuild»

**Пример запроса:**
> Не билдится, разберись и доведи до зелёной сборки.

---

## 4) `mvp-ux-polish-pass`

**Когда:** нужно быстро улучшить UX без большого редизайна.  
**Триггеры:**
- «выглядит хаотично»
- «сделай чище»
- «улучши читаемость»
- «полируй UX»

**Пример запроса:**
> Экран выглядит шумно, сделай короткий UX polish pass.

---

## 5) `release-smoke-gate`

**Когда:** перед финальным ответом по значимым изменениям (UI/логика/несколько файлов).  
**Триггеры:**
- «проверь перед финалом»
- «сделай strict smoke-check»
- «прогони release smoke gate»

**Пример запроса:**
> Перед финалом прогони release-smoke-gate и дай PASS/FAIL.

---

## Рекомендуемый формат запросов

Чтобы получать лучший результат за 1 проход, добавляй:
- **цель** (что улучшить),
- **границы** (что не трогать),
- **критерий готовности** (как поймём, что ок).

**Шаблон:**
> Цель: …  
> Не делаем: …  
> Готово, когда: …
